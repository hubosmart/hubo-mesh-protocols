# hubp 串口协议规范

本文规定 Hubo S3 终端（主机）与底板协处理器 CH32（从机）之间的 hubp 串口协议的线上格式与主机侧行为。本文只描述线上协议，不涉及 CH32 固件内部实现。

## 1. 概述与角色

- **主机（Host）**：Hubo S3 终端（ESP32-S3）。主动发送命令，接收应答与事件。
- **从机（Device）**：CH32 协处理器。负责键盘矩阵、滚轮等输入，应答命令并主动推送事件。
- 协议是面向行的 ASCII 文本协议，分三类帧：命令（主机到从机）、应答（从机到主机）、事件（从机到主机，主动推送）。
- 一次只有一个命令在途：主机发出命令后等待同序号的应答，期间收到的事件照常处理。

## 2. 物理层

物理层参数在协议层之外，由实现决定。以下是参考实现（Hubo S3 终端）的接法，第三方实现可自行选择串口、引脚与波特率：

| 项目 | 参考实现取值 |
| --- | --- |
| 串口 | UART1，8 数据位、无校验、1 停止位、无硬件流控 |
| 波特率 | 115200 |
| 主机 TX / RX | GPIO43 / GPIO44 |
| 中断线（可选） | GPIO46，主机输入、上拉，下降沿触发 |

中断线是可选的，协议不要求其存在：

- 配置了中断线时，按参考实现的用法，从机有待取事件即把该线拉低；主机检测到低电平后，用 `HID:EVT:READ` 把事件取空（见 5.2 节）。
- 未配置中断线时，主机依靠从机主动推送的事件；若从机能力里没有 `EVT:PUSH`（见 5.1 节），主机每 20 ms 轮询一次 `HID:EVT:READ`。

## 3. 帧与行格式

### 3.1 行

- 一帧为一行文本，以换行符 `\n`（0x0A）结尾。
- 接收时忽略回车符 `\r`（0x0D）；空行忽略。
- 一行（不含换行符）最长 127 字节（缓冲区 `HUBP_PROTOCOL_LINE_MAX` = 128 字节，含结尾 NUL）。超长的行整行丢弃，直到下一个 `\n` 才恢复接收，不产生帧。
- 无法识别的行（不符合下面任何一种格式）静默忽略，不产生帧。
- 一个字节流中可以出现任意分片或合并：解析器逐字节喂入，只在遇到 `\n` 时才产出帧（见第 9 节示例会话）。

### 3.2 命令帧（主机到从机）

```
#NN:<命令>\n
```

- `NN`：两位十进制序号，`00`～`99`，主机每发一条命令加 1，到 99 后回绕到 00。
- `<命令>`：ASCII 文本，长度须小于 96 字节，否则主机不发送。
- 例：`#07:SYS:PING\n`

### 3.3 应答帧（从机到主机）

```
#NN:ACK:<正文>\n       成功
#NN:ERR:<正文>\n       失败
```

- `NN` 是被应答命令的序号。主机只接受与当前在途命令序号相同的应答；序号不符的应答被忽略。
- `<正文>` 是应答内容，主机原样取出，不做进一步语法限定（各命令的正文见第 5 节）。
- 例：`#07:ACK:SYS:PING:PONG\n`、`#03:ERR:E102:UNKNOWN\n`

### 3.4 事件帧（从机到主机）

```
!EVT:<正文>\n
```

事件由从机主动推送，不带序号，也不需要应答。正文格式见第 6 节。

## 4. 帧类型

参考实现把解析结果归为 `HUBP_FRAME_*` 四类：

| 枚举 | 含义 |
| --- | --- |
| `HUBP_FRAME_INVALID` | 无效/未识别（值 0）。解析函数不会产出这一类，它只是零值占位。 |
| `HUBP_FRAME_ACK` | 成功应答，对应 `#NN:ACK:` 行；带序号与正文。 |
| `HUBP_FRAME_ERROR` | 失败应答，对应 `#NN:ERR:` 行；带序号与正文。 |
| `HUBP_FRAME_EVENT` | 事件，对应 `!EVT:` 行；无序号，只有正文。 |

## 5. 命令与应答

下表是参考实现使用的全部命令（共 13 条）。方向均为主机到从机，由从机用 ACK 或 ERR 应答。

| 命令 | 用途 | 参考实现中的使用 |
| --- | --- | --- |
| `SYS:INFO` | 查询固件信息 | 握手第 1 步 |
| `SYS:CAPS` | 查询能力 | 握手第 2 步 |
| `SYS:DETECT` | 检测 | 握手第 3 步，失败不影响握手 |
| `SYS:MODE:KB` | 切换到键盘模式 | 握手第 4 步 |
| `SYS:MODE:IDLE` | 切换到空闲模式 | 已定义，参考实现未使用 |
| `SYS:PING` | 保活 | 每秒一次；应答正文 `SYS:PING:PONG` |
| `HID:KEY:SCAN:ON` | 开启按键扫描与上报 | 握手第 5 步；熔断恢复 |
| `HID:KEY:SCAN:OFF` | 关闭按键扫描与上报 | 已定义，参考实现未使用 |
| `HID:KEY:MODE:ACTIVE` | 按键上报进入活动模式 | 握手第 6 步（仅从机支持 `EVT:PUSH` 时）；熔断恢复 |
| `HID:KEY:MODE:SLEEP` | 按键上报进入休眠模式 | 由主机应用按需调用 |
| `HID:KEY:RAWRESET` | 复位原始键值状态 | 已定义，参考实现未使用 |
| `HID:KEY:RAW:<n>` | 带键号参数的前缀命令（`<n>` 为键号十进制数） | 已定义，参考实现未使用 |
| `HID:EVT:READ` | 取出一条排队事件 | 见 5.2 节 |

说明：

- 本文对各命令的 ACK 正文，只规定代码里能确认的部分（见下）；其余命令的 ACK 正文（以及 ERR 正文的错误码表）在参考实现中不被解析，**协议层未规定**。参考实现里唯一出现的 ERR 示例是 `E102:UNKNOWN`（见测试用例），含义推断为未知命令，但错误码表未在代码中给出。
- 主机对任何命令的处理一致：ACK 视为成功，ERR 视为失败，超时视为无应答。

### 5.1 握手：`SYS:INFO`、`SYS:CAPS`、`SYS:DETECT`

握手按下列顺序依次发送命令，每条命令的超时为 500 ms：

1. `SYS:INFO`。主机从应答正文里取出两个字段（字段以 `:` 分隔）：
   - `:FW=<固件版本>`：主机最多保存 15 个字符。
   - `:PROTO=<协议版本>`：主机最多保存 7 个字符。
   - 正文里还可带 `SKU=<id>` 字段，它决定从机把键盘矩阵配成 4×11（SKU1）还是 4×4（SKU2）。参考实现只记录日志，不解析它。字段的具体排列顺序未规定。
2. `SYS:CAPS`。主机在应答正文里按子串查找能力标记：
   - 含 `EVT:PUSH`：从机会主动推送事件（`!EVT:`）。
   - 含 `KEY:RELEASE`：从机上报按键释放事件。
   - 含 `WHEEL:1`：从机带滚轮。
   - 正文里另有 `BL:1` 之类的标记，含义由实现定义，参考实现只记日志，不使用。
3. `SYS:DETECT`：应答只记日志；失败不中止握手。
4. `SYS:MODE:KB`。
5. `HID:KEY:SCAN:ON`。
6. 若 CAPS 含 `EVT:PUSH`，再发 `HID:KEY:MODE:ACTIVE`。

任一必需步骤（1、2、4、5、6）失败，握手失败；参考实现在 100 ms 后重试。全部成功后，主机视从机为在线，并开始保活。

在握手之前，参考实现还会先发送 `\n\n\nPING\n`，用于清除线路上可能的残余字符并唤醒旧版从机；这不是协议要求的一部分，从机应忽略无法识别的行（见 3.1 节）。

### 5.2 事件读取：`HID:EVT:READ`

- 应答正文为 `HID:EVT:NONE`：当前无排队事件。
- 否则应答正文为 `HID:EVT:<事件体去掉前缀 HID:>`，例如 `HID:EVT:KEY:K01:Q:PRESS:T=123`。主机在前面补上 `HID:`，还原成与推送事件相同的事件体 `HID:KEY:K01:Q:PRESS:T=123`。
- 应答正文既不是 `HID:EVT:NONE`、也不以 `HID:EVT:` 开头时，主机视为无效应答。
- 主机每次最多连续取 64 条，取到 `HID:EVT:NONE` 即停止。每条取回的命令超时 300 ms。

同一事件可能既被推送、又留在队列里被拉取补取，主机用去重环压掉重复（见 6.4 节）。

### 5.3 保活：`SYS:PING`

主机在线时每 1 秒发送一次 `SYS:PING`（超时 300 ms）。无应答则主机判定从机离线，并重新握手。

## 6. 事件

事件正文（`!EVT:` 之后的部分）分三类。

### 6.1 按键事件

```
HID:KEY:K<nn>:<键名>:PRESS[:T=<毫秒>]
HID:KEY:K<nn>:<键名>:RELEASE[:T=<毫秒>]
```

- `<nn>`：键号，十进制，1～44；超出范围的事件被丢弃。
- `<键名>`：如 `Q`、`FN`、`T`、`WHL_UP`（测试用例中出现的值）；主机不解析键名，只用键号。完整键名表未在协议层规定。
- 动作：以 `:PRESS` 或 `:RELEASE` 结尾，或在 `:T=` 之前出现 `:PRESS` / `:RELEASE`。
- `T=<毫秒>`：从机时间戳，十进制毫秒，可选。旧版从机不带该字段，此时主机把时间戳视为 0。

### 6.2 滚轮事件

```
HID:WHEEL:UP:PRESS|RELEASE[:T=<毫秒>]
HID:WHEEL:DOWN:PRESS|RELEASE[:T=<毫秒>]
HID:WHEEL:PUSH:PRESS|RELEASE[:T=<毫秒>]
```

参考实现把三个方向映射成固定的内部键码：`UP` 为 11（滚动增量 -1），`DOWN` 为 22（增量 +1），`PUSH`（按下滚轮）为 33。

### 6.3 系统事件

- `SYS:EVT_OVERFLOW:<n>`：从机事件队列溢出，丢失了 `n` 条事件。
- `SYS:BOOT:...`：从机刚启动/复位。主机收到后视从机为离线并重新握手。
- `SYS:RESET:IDLE_TIMEOUT`：从机在一段时间（代码注释中为 3 秒）收不到主机数据后，关闭按键上报并回到键盘模式，同时发出此事件。主机收到后须重发 `HID:KEY:SCAN:ON`（及 `HID:KEY:MODE:ACTIVE`，若从机支持 `EVT:PUSH`）以恢复上报。这也是主机必须持续保活的原因。
- 其他以 `SYS:` 开头的事件：参考实现只记录日志；正文格式未规定。

### 6.4 事件体长度、归一化与去重

- 事件体最长 63 字节（`HUBP_EVENT_BODY_MAX` = 64，含结尾 NUL）。
- 归一化：事件体若以 `KEY:` 或 `WHEEL:` 开头（缺 `HID:` 命名空间），可在前面补 `HID:`，使推送与拉取两条路径得到同一形式。参考实现提供了该归一化函数并有测试用例覆盖；参考实现的推送接收路径当前直接使用 `!EVT:` 后的正文，不调用它，因此从机应在 `!EVT:` 之后直接发送带 `HID:` 的完整事件体。
- 去重：只对带 `:T=` 时间戳的事件体做去重，环深度为 64 条；与环内某条字节相同的事件体视为重复，丢弃。不带 `:T=` 的旧版事件体永不去重（相同内容可能是下一次真实按下）。

## 7. 错误与超时处理

| 情形 | 主机处理 |
| --- | --- |
| 命令无应答 | 超时，由调用方决定重试；握手相关命令超时为 500 ms，`HID:EVT:READ` 与 `SYS:PING` 为 300 ms |
| 收到 ERR 应答 | 命令失败，正文原样交给调用方 |
| 应答序号与在途命令不符 | 忽略，继续等待 |
| 行超长、无法识别、不是 ACK/ERR/EVT | 静默丢弃，不影响后续行 |
| 保活失败 | 判定离线，重新握手 |
| 收到 `SYS:BOOT:` | 判定离线，重新握手 |
| 收到 `SYS:RESET:IDLE_TIMEOUT` | 重发 `HID:KEY:SCAN:ON`（以及视能力 `HID:KEY:MODE:ACTIVE`） |
| 事件解析失败（按键号越界、动作缺失等） | 丢弃该事件 |
| 主机本地事件队列（64 条）满 | 丢弃新事件，下次读取时先给出一条 `溢出` 通知，并清空队列，由上层重置修饰键状态 |

握手整体等待上限（参考实现的 `hubp_client_handshake`）为 6 秒。

## 8. 版本与兼容

- 协议版本由从机在 `SYS:INFO` 的 `:PROTO=` 字段报告；固件版本在 `:FW=` 字段。版本号的取值与演进规则未在代码中规定。
- 能力协商通过 `SYS:CAPS` 完成（见 5.1 节）：`EVT:PUSH`、`KEY:RELEASE`、`WHEEL:1`。主机应按能力决定行为，而不是按版本号。
- 旧版从机兼容：不支持 `EVT:PUSH` 的从机，主机采用轮询拉取；不带 `:T=` 时间戳的事件体，主机不做去重。

## 9. 示例会话

以下示例来自参考实现的测试用例。`>` 表示主机发出，`<` 表示从机发出。

**分片与合并**。字节流把一条事件分成两段到达，紧接着一条应答在同一次读取里一并到达，解析器产出两帧：

```
< !EVT:HID:KEY:K01:Q:PRE            （第一段，无换行，不产出帧）
< SS:T=123\n#07:ACK:SYS:PING:PONG\n （第二段）
```

产出：

- 事件帧，正文 `HID:KEY:K01:Q:PRESS:T=123`
- 应答帧（ACK），序号 7，正文 `SYS:PING:PONG`

**超长行恢复**。连续 140 个字节无换行：解析器进入丢弃状态，直到遇到换行才恢复。随后的合法行照常解析：

```
< XXXX...（共 140 个 X）\n          （整行丢弃，不产出帧）
< #03:ERR:E102:UNKNOWN\n            （产出 ERROR 帧，序号 3，正文 E102:UNKNOWN）
```

**事件解析**：

| 事件体 | 结果 |
| --- | --- |
| `HID:KEY:K37:FN:RELEASE:T=456` | 按键 37，释放，从机时间戳 456 ms |
| `HID:WHEEL:UP:PRESS:T=500` | 滚轮上，内部键码 11，增量 -1，按下 |
| `HID:WHEEL:DOWN:RELEASE:T=501` | 滚轮下，内部键码 22 |
| `HID:WHEEL:PUSH:PRESS:T=502` | 滚轮按下，内部键码 33 |
| `SYS:EVT_OVERFLOW:9` | 溢出通知，丢失 9 条 |
| `HID:KEY:K05:T:PRESS` | 按键 5，按下，无时间戳（时间戳为 0） |

**去重**：

```
HID:KEY:K01:Q:PRESS:T=123    接受
HID:KEY:K01:Q:PRESS:T=123    重复，丢弃
HID:KEY:K01:Q:RELEASE:T=124  接受
（再接受 64 条其他事件后，环被覆盖）
HID:KEY:K01:Q:PRESS:T=123    再次接受
HID:KEY:K01:Q:PRESS          旧版（无 T=），永远接受
```

**归一化**：

```
KEY:K05:T:PRESS:T=260609    →  HID:KEY:K05:T:PRESS:T=260609
WHEEL:UP:RELEASE:T=260700   →  HID:WHEEL:UP:RELEASE:T=260700
SYS:EVT_OVERFLOW:3          →  SYS:EVT_OVERFLOW:3（不变）
```

**典型命令往返**（示意，序号与应答正文以实际从机为准）：

```
> #07:SYS:PING\n
< #07:ACK:SYS:PING:PONG\n
```
