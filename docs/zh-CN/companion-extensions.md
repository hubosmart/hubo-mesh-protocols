# C3 电台伴随协议扩展规范

Hubo S3 终端通过 BLE 连接 MeshLoRa C3 电台，使用标准的 MeshCore 伴随（companion）协议。本文只规定 C3 电台固件在标准协议之外的扩展：自定义变量、带范围的文本发送命令，以及默认射频参数与发射功率上限。标准命令本身（联系人、消息、频道等）请参考 MeshCore 的伴随协议文档。

## 1. 使用的标准命令

自定义变量复用 MeshCore 标准伴随协议里的三个码，不新增命令码：

| 名称 | 码 | 方向 | 说明 |
| --- | --- | --- | --- |
| `GET_CUSTOM_VARS` | 40 | 主机到电台 | 读取全部自定义变量 |
| `SET_CUSTOM_VAR` | 41 | 主机到电台 | 写一个自定义变量 |
| `RESP_CUSTOM_VARS` | 21 | 电台到主机 | `GET_CUSTOM_VARS` 的应答 |

标准应答码：`RESP_OK` = 0，`RESP_ERR` = 1（后跟 1 字节错误码）。本文涉及的错误码：

| 错误码 | 名称 |
| --- | --- |
| 1 | `UNSUPPORTED_CMD` |
| 2 | `NOT_FOUND` |
| 3 | `TABLE_FULL` |
| 4 | `BAD_STATE` |
| 5 | `FILE_IO_ERROR` |
| 6 | `ILLEGAL_ARG` |

### 1.1 读取：`GET_CUSTOM_VARS`

请求帧：

```
[40]
```

应答帧：

```
[21] "name:value,name:value,..."
```

- 第 1 字节为 21，其后是 ASCII 文本，没有结尾 NUL；帧长即文本长度加 1。
- 文本由若干 `name:value` 对组成，以 `,` 分隔；`name` 与 `value` 以第一个 `:` 分隔。
- 固定的变量（`radio.rxgain`、`hubo.scope_tx`）总在最前面，随后是传感器提供的变量。
- 电台在追加每个传感器变量之前检查已写入的文本长度；累计超过 140 字节后不再追加后面的变量，因此变量太多时尾部变量可能缺失。
- 读取 `radio.rxgain` 时若底层射频芯片读取失败，电台回 `ERR` 帧（`BAD_STATE`），而不是 `RESP_CUSTOM_VARS`。

应答示例（带 GNSS 的电台，未定位）：

```
radio.rxgain:1,hubo.scope_tx:1,gps:1,gps_interval:0,gps_fix:0,gps_sats:0,gps_nmea:37,gps_lat:,gps_lon:,gps_alt:
```

### 1.2 写入：`SET_CUSTOM_VAR`

请求帧：

```
[41] "name:value"
```

- 帧长至少 4 字节；`name` 与 `value` 以第一个 `:` 分隔，缺少 `:` 时回 `ERR(ILLEGAL_ARG)`。
- 成功回 `OK`；`name` 不存在、只读或 `value` 非法时回 `ERR(ILLEGAL_ARG)`。
- 写入成功且该变量需要持久化时，电台先把偏好写入存储，写存储失败则回滚并回 `ERR(FILE_IO_ERROR)`。

## 2. 自定义变量

C3 电台提供下表共 10 个变量。其中前 2 个固定存在；`gps` 开头的 8 个变量只在带 GNSS 模块的电台固件（GNSS 版）上存在，不带 GNSS 的电台不会出现它们。

| 名称 | 读写 | 取值 | 含义 |
| --- | --- | --- | --- |
| `radio.rxgain` | 读写 | `0` 或 `1`（单个字符，写入时必须恰好如此） | 射频接收增益模式（RX boosted gain）。`1` 为开启。写入后电台读回确认，并保存到偏好；出错时回滚。 |
| `hubo.scope_tx` | 只读 | 恒为 `1` | 电台支持带范围的文本发送命令（见第 4 节）。 |
| `gps` | 读写 | `0` 或 `1` | GNSS 开关；`1` 上电并开始接收 NMEA 语句，`0` 断电并清空状态。默认 `0`（上电默认关闭）。写入的值以首字符是否为 `1` 判定，并保存到偏好。 |
| `gps_interval` | 读写 | 非负整数，单位秒；偏好中限制在 0～86400 | 仅保存，不影响行为：GNSS 开启后连续工作，不按此间隔开关。默认 `0`。 |
| `gps_fix` | 只读 | `0` 或 `1` | 是否有有效定位（最近一条 RMC 状态为 A，或 GGA 质量指示大于 0）。 |
| `gps_sats` | 只读 | 非负整数 | 卫星数，取自 GGA 语句。 |
| `gps_nmea` | 只读 | 非负整数 | 校验和正确的 NMEA 语句累计数（对 10^9 取模）。室内没有定位时，也可借此确认 GNSS 串口已通。 |
| `gps_lat` | 只读 | 十进制度，6 位小数，南纬为负，如 `12.345678`；没有定位时为空 | 纬度。 |
| `gps_lon` | 只读 | 十进制度，6 位小数，西经为负，如 `-98.765432`；没有定位时为空 | 经度。 |
| `gps_alt` | 只读 | 整数米，可为负；没有定位时为空 | 海拔（四舍五入到整米）。 |

说明：

- 空值写法是 `gps_lat:`（冒号后无内容），仍是合法的 `name:value` 对。
- 电台断电（`gps` 为 `0`）后 `gps_fix`、`gps_sats`、`gps_nmea` 归零，三个位置变量为空。
- 有定位且 GNSS 开启时，电台还把经纬度和海拔用作节点自身位置（用于 advert 与自身信息），并在遥测里带 GPS（需要请求方具有位置权限）。
- 上表之外的变量名写入，电台回 `ERR(ILLEGAL_ARG)`。

## 3. 终端如何识别 C3 的能力

终端（Hubo S3）在连接后发一次 `GET_CUSTOM_VARS`，解析应答得到能力：

| 能力 | 判定 |
| --- | --- |
| 接收增益可用 | 应答里出现 `radio.rxgain`，其值为 `0` 或 `1` |
| 带范围文本发送可用 | `hubo.scope_tx` 值为 `1` |
| GPS 可用 | 应答里出现 `gps`，其值为 `0` 或 `1` |
| GPS 已开启 | `gps` 为 `1` |
| 已定位 | `gps_fix` 为 `1`；位置变量 `gps_lat`、`gps_lon`、`gps_alt` 三项都有值才算拿到位置 |

终端检测到 GPS 可用且已开启时，约每 2 秒重读一次 `GET_CUSTOM_VARS` 以刷新定位状态。

终端的解析是严格的，整条应答只要出现下列任何一种情形就被整体拒绝（视为不可用，不使用其中任何变量）：

- 应答首字节不是 21，或文本中含 NUL 字节。
- `radio.rxgain`、`hubo.scope_tx`、`gps`、`gps_fix` 的值不是单个字符 `0` 或 `1`。
- `gps_sats`、`gps_nmea` 不是 1～9 位纯十进制数字；`gps_sats` 大于 255。
- `gps_lat` / `gps_lon` 有值时不是十进制度：可带负号，整数部分最多 3 位，小数部分 1～6 位，绝对值不超过 90 / 180；`gps_alt` 有值时不是最多 6 位的整数（可带负号）。
- 上述任一变量重复出现。

未列入上表的变量名，终端解析时忽略。键名必须整段相等：`gps` 不会匹配 `gps_interval`。

终端写入的变量：

- 接收增益：`[41] "radio.rxgain:0"` 或 `"radio.rxgain:1"`（共 15 字节）。
- GPS 开关：`[41] "gps:0"` 或 `"gps:1"`（共 6 字节）。

## 4. 带范围的文本发送（`hubo.scope_tx`）

当 `hubo.scope_tx` 为 `1`，电台支持在标准伴随命令 54（`SET_FLOOD_SCOPE_KEY`）上的一个扩展子命令：发送一条频道文本，并只对这一条消息指定 flood 范围，不改变电台的默认范围或存储的配置。

请求帧（长度 26～176 字节）：

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 1 | 命令码 54 |
| 1 | 1 | 子命令，固定为 2 |
| 2 | 1 | 范围种类：0 使用电台默认范围，1 不带范围（unscoped flood），2 使用下面给出的密钥 |
| 3 | 16 | 范围密钥；种类为 2 时必须不全为 0，其他种类填 0 |
| 19 | 1 | 保留，必须为 0 |
| 20 | 1 | 频道序号；须小于电台的频道数量 |
| 21 | 4 | 发送时间戳，小端序 32 位无符号整数 |
| 25 | N | 文本，UTF-8，N 为 1～151 字节；不得含 NUL，须是合法 UTF-8 |

应答：成功回 `OK`；参数非法（格式、频道序号、文本无效或加上节点名后超长）回 `ERR(ILLEGAL_ARG)`；频道不存在回 `ERR(NOT_FOUND)`；发送队列满等发送失败回 `ERR(TABLE_FULL)`。该命令无论成败，处理完后电台都恢复原来的范围设置。

## 5. 默认射频参数与发射功率上限

C3 电台固件的编译期默认值：

| 参数 | 默认值 |
| --- | --- |
| 频率 | 433.650 MHz |
| 带宽（BW） | 62.5 kHz |
| 扩频因子（SF） | 8 |
| 编码率（CR） | 5（即 4/5） |
| 发射功率 | 10 dBm |
| 发射功率上限 | 10 dBm |
| 射频芯片 | SX1268（编译期默认；各板实际使用的芯片设置见 C3 仓库 README 的变体表） |

电台的约束：

- 发射功率在标准命令 `SET_RADIO_TX_POWER` 里被限制在 -9 dBm 到上限 10 dBm；超出时回 `ERR(ILLEGAL_ARG)`。上限同时在标准的自身信息应答（`SELF_INFO`）里通过“最大发射功率”字段报告（紧跟当前发射功率之后的 1 字节）。
- 射频参数（`SET_RADIO_PARAMS`）在应用前被校验：频率 410～493 MHz，SF 5～12，CR 5～8，带宽须是 7.8、10.4、15.6、20.8、31.25、41.7、62.5、125、250、500 kHz 之一；发射功率 -9～10 dBm。校验失败回 `ERR(ILLEGAL_ARG)`。
- 以上默认值是固件编译期的取值；电台首次启动后以保存在偏好里的当前值为准。
